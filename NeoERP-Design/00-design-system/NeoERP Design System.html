01

Principles

NeoERP is a dense, multi-tenant administrative product. The system optimises for scanning large amounts of structured data without fatigue.

PrincipleWhat it means in practice
Monochrome by defaultNeutral greys carry the entire interface. Colour is reserved exclusively for status — a coloured element always means something is active, pending, at risk, or informational. Never decorative.
Borders, not shadowsStructure comes from 1px hairlines. Shadow appears only when something genuinely floats above the page: modal, toast, mobile drawer.
Data first, chrome lastType sizes stay small and tight (13.5px body). Padding is generous enough to breathe, never so generous it reduces rows on screen.
One accent, high contrastThe accent is near-black in light mode and near-white in dark mode. Primary actions are unmistakable without a brand hue.
Density is a user choiceThree density modes rescale padding and control heights via tokens. Layout and type scale never change — only spacing.
Same system, every breakpointNothing is mobile-only. The sidebar becomes a drawer, grids collapse, tables become cards — all from the same component set.

Rules

  • Never below 12px in product UI; never below 11px for uppercase overlines. On mobile, tap targets stay at 44px regardless of text size.
  • Tabular figures (font-variant-numeric: tabular-nums) on every numeric table column, KPI value and counter so digits align vertically.
  • Weights used: 400 body · 500 interactive & labels · 600 titles & overlines · 700 headings & metrics. No 300, no 800.
  • Line length caps at ~72 characters for prose blocks; table cells and labels are unconstrained.

Motion

Motion confirms cause and effect. Nothing decorative, nothing longer than 400ms.

Source of truth — every duration here is a CSS custom property in styles.css (--m-instant … --m-slow, --ease-out) and a token in neoerp-tokens.json. The former CSS-only strays at 100ms and 200ms have been folded into quick and dialog. All motion is wrapped in prefers-reduced-motion.
DurationTokenUsed for
80msmotion/instantHover backgrounds, border colour, button fills
120msmotion/quickSwitch knob travel, checkbox fill
150msmotion/fastScrim fade, chevron rotation, tab swap
180msmotion/dialogModal enter — 12px rise, 0.98 → 1 scale
220msmotion/baseDrawer slide in / out
400msmotion/slowBar chart growth, progress fill, layout reflow
Easing — cubic-bezier(0.2, 0.8, 0.2, 1) for anything that travels or scales. Plain ease for colour and opacity.

Feedback & states

Every screen inherits these rather than inventing its own. They live in feedback.css and are rendered in full in the component library.

Loading

StateRule
SkeletonMirrors the exact geometry of the content it replaces so nothing shifts on load. Shimmer is a 1.4s linear-gradient sweep on bg/soft → bg/hover, disabled under prefers-reduced-motion. Never show for under 200ms — use a spinner instead.
Spinner13px, 1.5px ring, text/disabled track with text/secondary head. An 18px variant for overlays, and an on-accent variant for use inside primary buttons.
Progress bar6px, pill radius, accent fill, 400ms ease-out on width. Always paired with a count and, for anything over ~10s, a time estimate.

Errors

StateRule
Field errorBorder switches to status/danger-text, focus halo to status/danger-bg. Message sits below with a 14px alert icon and says what to change, not that something is invalid.
Form bannerSummarises and lists every failure as bullets. Sits directly above the first field, inside the card or modal body — never as a toast.
Failed to loadFull state block with a retry as the primary action and a support escalation as secondary. Always shows a reference ID in mono at the bottom.
Card-level failureOne panel fails, the page keeps working. Retry lives in that card's header; the failure message stays inside its body.

Empty

Two distinct cases, never the same treatment.
  • No data yet — teaches what the thing is for and offers the first action as a primary button. Optimistic tone.
  • No results — a dead end. Echoes the search term, names any active filters, and offers a way back. No primary button, because creating something is not what the user was trying to do.
Geometry for both: 52×52 icon block at radius 14, title 600·16, body 13 tertiary, max-width 420 centred, padding 64/24.

System interruptions

StateRule
OfflineA persistent warning strip pins above the top bar with a pulsing dot and a manual retry. Content stays visible from cache; editing is disabled. Reconnecting swaps it for an info banner naming what is syncing.
Permission deniedTakes over the view — there is nothing useful behind it. Names the required role and the user's current role. Offers Request access. For a single blocked action, disable the button and put the reason beside it instead.
Out of scopeSame block, but names how many companies the user can manage out of the total.
Session expiredA modal, not a redirect — so unsaved work survives. Re-authenticate in place; the modal names what is being preserved.

Pending & partial failure

StateRule
Optimistic pendingThe row or control renders its new value immediately at 55% opacity with pointer events off, plus an inline Applying… label.
AutosaveState reads out in the card header: Saving… → Saved. An unsaved-changes dot uses status/warning-dot.
Row failureRow background goes status/danger-bg, the reason replaces the row's subtitle, and a retry replaces the row actions.
Partial failureNever roll a bulk action back silently. A warning header states the ratio, then one row per failure naming the item and the exact reason, with Retry failed scoped to just those.

Tenant lifecycle covers companies and users. Workflow states cover anything with a queue — tickets, approvals, leave requests — and arrive with the HRMS and CRM modules. Priority uses stepped bars so it survives greyscale and colour-blindness, unlike a colour-only tag.

Figma build brief

Hand this section, the tokens file, and the live prototype to whoever builds the library.

Build order

  1. Variables — create a theme collection with Light and Dark modes and add every colour token from section 02. Create a density collection with Compact, Regular and Cozy modes for the spacing and sizing numbers in section 04.
  2. Text styles — build the 14 styles from section 03 using Inter Tight and JetBrains Mono. Name them exactly as listed so they map to code.
  3. Effect styles — three shadow levels per theme mode from section 05.
  4. Icon set — 24 × 24 frames, 1.75 stroke, round caps, no fill, all set to currentColor behaviour via a single colour layer.
  5. Primitives — button, text field, pill, switch, checkbox, avatar, icon button. Auto Layout, variables bound for padding and height.
  6. Composites — card, KPI tile, table row, tab bar, stepper chip, nav item, activity row, role card, toast, modal.
  7. Feedback set — skeleton variants, banner (5 tones), state block (empty / error / permission), offline strip, partial-failure list, spinner and progress. Section 10 has the rules.
  8. Screen frames — 1440 × 900, 820 × 1180 and 390 × 844 for each of the eleven screens listed below.
