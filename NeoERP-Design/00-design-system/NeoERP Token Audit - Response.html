01 The ramp decision

Confirmed: four levels, your values. We considered the three alternatives you named and rejected all three.

Adopted

Four levels stay, tertiary moves with quaternary

The four levels aren't decorative — they carry a real hierarchy in the tables: cell value, secondary line, metadata, column header. Collapsing to three would force column headers and row metadata onto the same grey, and the header is the thing that stops being findable when you scan 2,000 tenants.

Not the three-level ramp for that reason. Not reclassifying quaternary as non-text — it carries column headers, group labels and placeholders; that's text by any definition, and renaming the role wouldn't make it legible. Not lightening bg/soft, because at 4.5:1 the greys would need it near-white, and bg/soft is the only thing separating a table header from the page in a system with no colour to spend.

Shipped: tertiary #5F5F5F, quaternary #707070 light, quaternary #8A8A8A dark — your values, unchanged. The step between tertiary and quaternary is now 17 points of luminance instead of 48, which is tighter than before but still legible as a hierarchy at 11px. If it reads flat in the Compose build at real density, tell us and we'll widen tertiary rather than touch quaternary.

03 Fixed in our files

All four web-side findings. You were right that they don't affect Compose — they were real bugs regardless.

Fixed

Focus, which was worse than "missing"

Not only was there no :focus-visible rule — the one focus style that existed was invisible. .input:focus drew a 3px halo in bg/soft on a white page: a 1.04:1 ring. It looked like a focus treatment in code review and rendered as nothing.

Now: a focus token group (ring colour per theme, 2px width, 2px offset, plus a soft inner halo for fields) and one :focus-visible rule covering buttons, icon buttons, nav items, tabs, role cards, chips, links and inputs. Checkbox and switch hide their real input, so the ring is drawn on the visual proxy. Inside overflow:hidden parents the offset is inverted so the ring isn't clipped.

Fixed

Reduced motion, using the pattern that already existed

Global guard on styles.css, matching feedback.css. Everything drops to 1ms; the drawer slide, modal rise and toast entry are cancelled outright rather than shortened, since those three are the ones with actual travel.

Fixed

The prototype now consumes its own system

data-label added across companies.jsx and admins.jsx — the companies table, the warehouses table, and the admin users table. 17 of the 19 cells carry one; the two remaining are the first-column identity cells, where .tbl td:first-child suppresses the label by design and renders the name as the card's heading instead. Action cells carry data-label="" so they don't print a label for a button, matching the Component Library. Below 720px every row now reads as a labelled card.

Fixed

Touch targets, at every density

Below 720px there's now a hard 44px floor that overrides density: icon buttons, the menu button, search, small buttons, and the compact-density --btn-h/--field-h overrides. The switch grows to 44×26 with a 22px knob and the checkbox to 22px with a 44px hit area. The top bar keeps its 64px height on mobile instead of shrinking to 56, because 44px controls no longer fit in 56.

Token: density/$touchFloor: 44 records the rule so it isn't rediscovered per platform.

04 Your two requests

Answered

Elevation, portable

New elevation group — one y / blur / opacity triple per level, exactly as asked. The existing boxShadow group stays as the web rendering of the same three levels, and is now documented as derived rather than primary.

"elevation": {
  "1": { "y": "1",  "blur": "3",  "opacity": "0.06" },   // card resting
  "2": { "y": "4",  "blur": "16", "opacity": "0.10" },   // raised / hover
  "3": { "y": "16", "blur": "40", "opacity": "0.20" }    // modal, toast, drawer
}

Note: the opacities are the two CSS layers combined, so a single-layer Compose shadow at these values lands close to the web render rather than matching the top layer only. Shadow colour is pure black in both themes; dark theme raises opacity, it doesn't tint.

Partly

The fonts — we can't attach the binaries, but you don't need us to

Both are open licence, so the canonical files are better fetched from source than passed through us: Inter Tight and JetBrains Mono are both SIL Open Font License 1.1 and available as variable WOFF2 from Google Fonts and from their upstream repositories. What you need from the spec is the subset: Inter Tight at 400 / 500 / 600 / 700, JetBrains Mono at 400 / 500.

One thing to carry over: the web build sets font-feature-settings: "ss01", "cv11" on body — stylistic set 1 and the single-storey a alternate. Without those the digits and lowercase a differ visibly from every screenshot in the spec, which is the kind of mismatch that reads as a bug in review. Also enable tabular figures wherever numbers column up (metrics, table numerics, currency).
