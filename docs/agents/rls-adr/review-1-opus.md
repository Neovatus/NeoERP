Findings:
1. BLOCKER, D6 (and D7 if same shape). System policy `USING (current_setting('neoerp.system_job', true) IS NOT NULL)`: after one system-job transaction on a pooled connection the setting reads '' (not NULL) in later transactions, so IS NOT NULL is true; permissive policies OR together → later user requests on that connection see/UPDATE all companies' rows in queue/outbox/inbox tables and accounts_setups. Fix: read flags through owner functions with NULLIF (like neoerp_current_company()), scope policies `TO neoerp_accounts_app`, add tests in §5.2/§5.7: after a system or platform transaction, a user transaction on the same connection sees only its own rows.
2. MAJOR, D2 "remembers the company (transaction resource)". Spring does not suspend plain bound resources for REQUIRES_NEW (DimensionSetJdbcAdapter.kt:127-130). REQUIRES_NEW used in ExportSupport.kt:57-69, LedgerCheckJob, RecurringJournalJob, ScheduledReversalJob, DimensionSetRepository → inner transaction skips set_config on its new connection (empty reads, WITH CHECK failures). Savepoints undo set_config while the marker stays. Fix: marker in a TransactionSynchronization or on the ConnectionHolder, set_config again whenever the connection changes; tests for REQUIRES_NEW and savepoint.
3. MINOR, D6 syntax: `FOR SELECT, UPDATE` invalid (one command per policy); evidence cleanup and opening-import expiry likely need DELETE. Fix: one policy per command per table, listed in the catalog test.
4. MINOR, §1.2/§5.5: audit_outbox holds each company's payload_text and reason under org_id (V6__a0_baseline.sql:327-340); excluded, and the catalog check keys only on company_id. Fix: decide explicitly (RLS on org_id + relay system policy, or a named exception).
5. MINOR, D1 "reference tables stay read-only for the runtime role" — today the role has full rights (accounts-runtime-role.psql:36,40). Fix: REVOKE + RuntimeRoleCheck check in R2, or reword.
6. MINOR, D5 overstates FORCE on the owner (owner can ALTER TABLE … NO FORCE or set neoerp.migration). Say it guards only against accidental owner-connection use (D5, §6).
7. MINOR, D6 arch test: ACCOUNTS_JDBC_ADAPTERS is in the allowed packages (TenantRepositoryArchitectureTest.kt:288), so package allowlisting admits all 76 adapters. Fix: allowlist bindSystemJob by class.
8. MINOR, numbering: §3 D1–D8 and §7 D1–D10 reuse labels. Fix: rename one set (e.g. M1–M8). ADR-024 D5 cited as settled but ADR-024 is still a draft.
Checked, no gap for Accounts: composite (company_id, id) FKs, unique indexes lead with company_id or parent id, no SECURITY DEFINER / views / materialized views / COPY in main code, triggers run as invoker, one sequence (outbox).
