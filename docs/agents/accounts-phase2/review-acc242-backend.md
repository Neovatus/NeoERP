# Review: ACC-242 backend (D-172 country-chart enforcement)

Repo `NeoERP-BackEnd`, branch `codex/acc242-backend`, `d902615..52b3d8f` (single commit `52b3d8f`).
Independent read-only review, 2026-10-21. No Gradle run.

## What was checked

- **Concurrency.** `ChartReplaceService.apply` runs the country check inside the transaction, after `setups.findForUpdate` and the `CHART_UNCHANGED`/`CHART_UNKNOWN` checks, and before `ChartBuilder`/`chartReplacement.write`/`setups.update`/audit (ChartReplaceService.kt:98-101). `GoLiveService.apply` checks again after `findForUpdate` and before any write (GoLiveService.kt:171). The early check in `prefetchFacts` only saves the Org call. `GoLiveTest.newlyChosenChartRecheckedAfterBooksLockBeforeAnyMutation` shows the refusal comes from the second read, which runs inside the transaction after the lock, and that nothing is written. Preview only reads, so it needs no lock.
- **Permissions and reasons.** The controller is unchanged. Replace still needs `CHART.REPLACE` through `@AccountsEndpoint`. Go-live still calls `requireChartReplace` before the country check, both in prefetch and in apply. `chartReason` is still required whenever `chartDiffers`. Nothing is weaker than before.
- **"Keep current" exception.** When `chartDiffers` is false (`requestedChart == currentTemplate.code`), `target` is `currentTemplate`, and `chartVersion` must still equal the current template's version. A request therefore cannot switch charts, versions or kinds through this path. It also skips no other validation: acknowledgement, on/off checks, required roles and tax linking all still run. LIVE replay returns before the check, which is the existing idempotent behaviour.
- **No path for another country's chart.** All three paths that pick a new chart call `CountryChartPolicy.allowed`: go-live with a different chart, LIVE replace and preview. `allowed` compares kind and country against `choices()`, so a BASE target is refused whenever the country has a published COUNTRY chart.
- **Frozen files.** The diff touches no file under `src/main/resources` (no V21/V22 migration, no pack files).
- **Migration test.** The new test runs V20 → V21 (asserts checksum 639820139) → tenant edits the English label → V22. It checks that the edited English label survives, that the inherited local label and the label of a sibling code update, that ids, codes and rates are unchanged, and that `validate()` passes.
- **Docs.** §6.5 now has `companyName`. §6.6 and the error table have `CHART_NOT_FOR_COUNTRY` with its details and the keep-current exception.
- **Tests that now use "same-country alternatives".** The alternate charts are copies of the original foreign template with the country relabelled (`PK-ALT` from NO or SE, `NO-ALT` from SE). The tests therefore still exercise the same foreign chart structure: tax codes kept, tax links re-derived through roles, `TAX_ITEM_UNLINKABLE`, posting-guard races, isolation, refusal order and journals. The one coverage lost is "replace onto BASE". That target can no longer be reached for books whose country has a chart (it is now refused), so nothing reachable went untested. New tests assert that NO and BASE are refused on preview (READY and LIVE) and on replace, with `details` checked, and that refused requests write nothing (no data, audit rows or events). They also assert that BASE preview still works for a country without a chart, and that keeping the current BASE chart works without CHART.REPLACE and with Org down.
