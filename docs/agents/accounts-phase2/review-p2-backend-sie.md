# Accounts Phase 2 review, part 2 of 3: backend SIE and plumbing

Range `ae54277^..dev` (NeoERP-BackEnd, `services/accounts-service`, `docs/api`). Area: H-SE export (CP-HSE.1a/1c), import (1b/1d/1e), the accounts side of the file store, CFG-UPL-1, CP-EV-2 (V18). Paths are relative to `NeoERP-BackEnd/services/accounts-service/src/main/kotlin/com/neovatus/accounts/` unless they say otherwise.

Checked and found correct: OB plan balances exactly per draft, AR/AP held out to OBE, difference only with `resultTo`, drafts created and submitted through A1 in one transaction, and the confirmer cannot post (test `confirmerCannotPostSecondPersonPosts`). History approve uses one company lock: confirmer ≠ approver, or the Owner with a required reason and `owner_self_approval`. Approval writes only `historical_balances`, never postings. Export `#IB/#UB/#RES` follow HS-6/HS-7, with UB/RES tie-out against TB AFTER/BEFORE and `TOTALS_MISMATCH`. Each account gets one `#SRU`, picked by the sign of the closing balance. The CP437 table is correct (0xFF = NBSP), and a trailing `\` is dropped before a closing quote. Every SIE query is scoped by `company_id`; the parse and expiry workers use `SystemTenantScopes.forCompany`. File-store keys are server-made (import id or random UUID) under `FileScope(accounts, companyId)`; no client text reaches a path. Downloads need ATTACHMENT, scan CLEAN and no platform caller. The multipart reader is bounded in parts, header size, field size, total size and time. V17 and V19 are additive and safe.
