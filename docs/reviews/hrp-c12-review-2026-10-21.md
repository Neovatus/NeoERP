Low notes:

- **L-12a (Low).** `payroll-data.jsx:3996` and `payroll-setup.jsx:927`: `'{n} confidential employees not shown'.replace('{n}',…)` breaks the building-blocks text rule. Plurals must use `<plurals>`, and numbers must not be formatted inside a string; the current text also produces "1 confidential employees". **Fix:** use a plural key, and format the count with the number formatter.

## 3. Batch E: PASS

The following hold:

- **Other employments** (`hr-data.jsx:582-588`):
  - Same identity: the scoped `userId` must equal the viewer's `userId`, and a platform actor has a null `userId`, so it sees nothing.
  - HR.EMPLOYEE.READ is required in both the source and the target company.
  - Manager team scope is enforced in the source (`viewer.team.has(e.id)`) and in the target (`scoped.team.has(x.id)`).
- **Filing generation** (`payroll-data.jsx:2818-2828`):
  - The actor must be in the same company, must not be a platform actor, and must hold FILING.GENERATE.
  - Submitted filings are refused.
  - The runs must be non-empty, distinct, in the same company and all PAID.
  - Every refusal returns before `depositIds`, `status`, `file` or the log is written.
- **Legacy Norway import:** `payTaxCardImport` returns `IMPORT_PREVIEW_REQUIRED` and writes nothing (`payroll-data.jsx:2862-2865`).
- **Cost centres:** the HR job, add-employee, department and lifecycle forms use only `NeoSearchSelect`/`LcPick` over the Accounts list. When the list is empty they show read-only "unavailable" text with a clear action, and there is no free-text input (`hr-employee.jsx:697-698`, `hr-directory.jsx:537-538`, `hr-org.jsx:291`, `hr-lifecycle.jsx:1128`).

Low notes:

- **L-12c (Low).** `hr-data.jsx:561`: `hrCcName` renders `${c.code} ${c.label}`, but `hrCcList` (`:560`) has no `code` field. The result is "undefined Butikkdrift" in the job summary, the org view and the payroll "by cost centre" report. An unknown id also falls back to the raw id. **Fix:** map `code: c.code || c.id` in `hrCcList`, and render "—" or "Unknown cost centre" instead of the raw value.
- **L-12d (Low).** `payroll-data.jsx:2824`: generation checks that the stored `f.runs` are PAID, but not that they are complete. A PAID run in the same period and kind that is missing from `f.runs` is not detected (P4 links every PAID event in the period). **Fix:** derive the run set from the PAID runs of the period and kind, or refuse when one is missing.
